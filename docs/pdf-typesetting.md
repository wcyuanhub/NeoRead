# PDF 保留排版译文

保留排版模式使用 BabelDOC 0.6.4 重新生成译文 PDF，再由现有 PDF.js 显示。阅读和「导出译文 PDF」使用同一份生成文件。排版视图与连续文本模式共用原有句子、批注和跳转能力。

## 数据路径

1. Go 从当前解析清单与已保存译文建立快照，只包含状态为 complete、原文哈希一致的译文；图片和表格只使用已翻译图注，不把整张图的标签当作正文。重新翻译时可以继续使用已有的有效译文。
2. BabelDOC 独立子进程解析原 PDF，生成布局、段落、公式和样式的中间表示。适配层按页、几何位置及文本相似度，对应已保存段落或连续完整句子的译文，不调用模型或在线翻译服务。
3. BabelDOC 排版并生成单语译文 PDF。列表符号、引用方括号、省略号、脚注和重音符与真正公式分开处理。复杂公式保持精确向量校验；简单行内数学可在原文逐符号对应后合并普通文字和多个向量片段，例如正文 `n` 与公式 `= 9` 对应译文 `$n = 9$`。只对有限的线性符号做 Unicode 渲染，不把未支持的 LaTeX 命令印到 PDF 上。公式失败时，只有完整原句序列能精确划分且边界不切断公式/连字，才逐句替换并保留失败句的原文；无法安全划分时保留整段。
4. 排版后逐字核验中间表示与最终 PDF 的字形、位置和完整句序，输出 `positions.json`。只有整块全部句子核验通过才启用页面内语义文字层；旋转、裁切或不完整映射使用段落旁的完整译文浮层，保留既有段落组件及其交互，不在 PDF 页间插入文字。字符映射是否完整不代表 PDF 是否已写入译文。
5. 子进程正常退出、完成协议与文件及坐标验证通过、快照仍为当前版本后，Go 原子发布 PDF、统计和坐标。PDF.js 使用现有带 capability 的资源地址加载，支持分页懒加载、缩放、主题及按页视口同步。

快照摘要包含适配版本、解析清单和有效译文。更改译文或解析结果后自动生成新版本，不提供过时版本的资源。生成期间不覆盖已保存译文、不推进学习或翻译阶段。

### 原版布局与中文段落

成功对应的段落在替换正文前记录原始区域、字号、行距和对齐关系。居中标题根据原页或最近正文栏的轴线识别，左对齐小标题保持左对齐；短作者信息保留原页中心轴。中文在原段落框内重新断行，正文行距参考原文并限制在 1.18–1.30 倍 em；空间不足先压缩到不低于 1.12 倍，再以 2% 步长缩小字号，最小为原字号的 74%。不同段落不再受全篇最密集段落的统一缩放影响。

此版本不移动相邻段落，不向右扩展到栏间距，不改变图表和公式区域。原文框放不下时以 `layout_overflow` 失败，保留已有译文并显示可操作的提示，避免发布裁切、极小字号或跨栏的结果。固定原段落起点会在较短中文段落下方留下空白，这是保留位置的取舍；同栏协调和空间扩展尚未实现。中文正文保留原文衬线/无衬线与字重映射，不强制模拟截图中的某一种字体。

`GET /api/documents/{id}/translations/typeset` 查询状态，`POST` 创建或复用任务，均使用现有本地鉴权。状态包含等待译文、组件不可用、执行阶段、完成和受控失败原因。`GET /api/documents/{id}/translations/typeset/positions?revision=...` 返回当前生成版本的已核验字形位置，需要鉴权，旧版本返回冲突。坐标携带原文哈希及完整目标句快照，前端再次校验以拒绝重译后的旧位置。

生成完成与译文写入完整性分开表示：`status=complete` 表示文件已生成，`coverage=complete/partial` 表示快照中的已有译文是否全部注入页面；`savedSentences`、`writtenSentences`、`unwrittenSentences` 是去重后的保存句子数、成功注入句子数及未写入数，不是解析器段落数或交互坐标核验率。未写入原因限于原文对应、公式还原和预处理不可用。Go 校验快照句子总数、计数守恒及原因白名单后才发布；页面和导出结果提示未写入数量。已写入但坐标不完整的段落仍使用完整译文浮层。

## 开发与打包

需安装 [uv](https://docs.astral.sh/uv/)。第一次准备运行时需要联网下载 Python、依赖、字体和布局模型：

```sh
pnpm prepare:babeldoc
pnpm dev
```

准备脚本在 `.runtime/babeldoc/` 创建 portable Python 3.12.11、带哈希的锁定依赖、离线资产及 `worker.py`、`positions.py`、`layout.py`、`formulas.py`。开发脚本和桌面主进程通过 `NEOREAD_BABELDOC` 指向此目录；独立 Go 服务需显式设置这个环境变量为绝对路径。缺少运行时会显示组件不可用和重试入口。

`pnpm package` 在打包前准备运行时并将它复制到 `resources/babeldoc`。只在原生目标平台准备运行时，不在一台机器上交叉复制 Python/ONNX 二进制。当前 macOS ARM64 运行时约 1 GB，安装包体积会增加；本次只验证此平台的实际排版，未验证 Windows、Intel Mac 安装包及签名。

依赖固定在 `scripts/babeldoc/requirements.lock`。更新依赖时重新编译锁文件，并检查两个缓存路径补丁和固定版本的段落钩子；不能只放宽版本号。资源在准备阶段下载，任务阶段禁止 socket 连接；资源缺失时失败，不转为在线下载。

## 生命周期与恢复

生成任务注册到现有文档任务生命周期，删除文档、重新解析和关闭服务会取消并等待任务结束。全局一次运行一个排版子进程，单次上限 30 分钟。临时快照、中间表示及 BabelDOC 翻译缓存只在私有 `.pending-*` 目录中存在，成功/失败后清理；进程崩溃遗留目录在该文档下次生成时清理。

最终缓存位于 `<library>/cache/<documentId>/typeset/<revision>/`，只保留 `translation.pdf`、`result.json` 和 `positions.json`。坐标文件包含译文字形，属于文档缓存，不进入诊断日志。新版本成功发布后清理旧版本。取消导出仅终止前端轮询和下载，不取消其他阅读视图正在共享的生成任务。

## 阅读交互与导出

- 页面内句子沿用既有 `[data-translation-block]` / `[data-sentence]` 契约和段落事件：选句、复制、批注、划线、问答、悬停联动、搜索定位、原译文句子跳转及引用/图号跳转共用原有逻辑。透明字形按最终 PDF 位置放置，并依据浏览器字宽缩放，实际可见页面仍由 PDF.js 绘制。
- 页面中的「完整译文」和未映射段落旁的「译文」可以打开原有 Markdown/公式内容；「重译」复用段落翻译流程。浮层挂在当前阅读容器中，复用选句、批注和跳转事件，宽度限制在该阅读栏内并独立滚动。浮层不参与 PDF 页面尺寸及页间滚动计算。生成中或组件缺失时先显示原 PDF 并明确提示当前为原文，已有译文仍可通过段落按钮阅读。
- 批注同时校验原文哈希及保存的完整目标文本。视图间空白或 Markdown 展示差异只在既定句子窗口内恢复，歧义时不套用到整段。重译后的批注恢复继续使用原有服务端恢复流程。
- 「导出译文 PDF」使用相同生成页面，并写入勾选类型的译文批注、划线及问答评论。导出根据同一份句子/字形映射定位，跨块批注必须全部可定位；旧目标、未映射、歧义或无法完整放置的批注不写入，并显示数量。原文批注继续使用原文 PDF 导出。

## 限制与人工验收

- 不同解析器拆分段落不完全一致。跨块合并、缺句、公式结构或顺序不可靠时，生成 PDF 仍可能保留英文；阅读器通过段落旁的浮层提供完整译文。参考文献、图中标签和未翻译区域通常保留原文。补充译文暂不追加到导出的 PDF。
- 显式句子/搜索/批注跳转使用重排后字形位置；双栏连续滚动仍按页和视口跟随，不能保证逐行对齐。引用编号区间只给 PDF 中实际存在的数字建立链接，展开的完整译文沿用原有引用展示。
- 旋转页、裁切页、复杂公式及不完整字形映射使用段落译文浮层。仅验证两篇实际论文，不代表扫描件、复杂表格及所有字体均已覆盖。自动测试不代替浏览器选区与视觉验收。
- 原 PDF、已保存译文及批注不因排版失败而改变。不改变原 PDF 页数与纸张尺寸。

人工检查：

1. 打开已有完成译文的 PDF，切换「保留排版」，检查中文正文直接显示、图表与公式无明显重叠，翻页、缩放和深浅主题可用。
   对照第一页的原页、栏中心标题与左对齐小标题，检查标题轴线、作者上标、栏宽、正文行距及原段落起点；较短中文段落下的留白不应被其他栏内容占用。用窄栏及整行拉丁引用检查换行，确认没有跨栏或行重叠。
2. 在页面双击句子、选择短语，添加高亮、划线和问答；切换连续文本再切回，确认相同位置和内容。点击批注、搜索结果、引用与图号，检查双向跳转及悬停联动。
3. 点击未映射段落旁的「译文」，对其选句批注、重译；在映射段落使用「完整译文」展开，检查公式。确认打开和关闭浮层不撑高页面、不使左右两栏错页，超长译文在阅读栏内换行和滚动。
4. 修改译文，检查重新生成时完整译文仍可读、旧位置不生效；删除或重新解析时检查没有残留排版任务。
5. 勾选批注类型并导出译文 PDF，用系统预览查看批注位置及问答评论，检查未写入数量；原文批注使用原文 PDF 导出。

自动检查：`pnpm typecheck`、`pnpm test`、`pnpm build`。Python 适配边界测试使用准备好的 Python，并将 `PYTHONPATH` 指向 `.runtime/babeldoc/site`，执行 `python -m unittest discover -s scripts/babeldoc -p 'test_*.py'`。覆盖完整句序、重复句、连字、最终字形/位置不一致、源/目标过期、坐标边界、鉴权和跨块批注整体导出。页面结构回归使用三页 PDF 与超长译文，检查未展开正文不进入页间文档流、浮层位于固定页面以外、页面尺寸不变及打开浮层不改变文档滚动位置；视觉仍需人工验收。

排版适配的 Python 回归额外覆盖标题/左对齐识别、逐行居中、末尾上标、字号不被重复缩放、固定框溢出及全篇缩放隔离。公式边界回归覆盖列表符号、分离方括号、重复表达式、文字/向量片段组合、拒绝凭空新增及有损转换、失败句局部保留、禁止切断公式/连字、去重覆盖统计和拒绝无效完成协议。

## 第三方许可证

BabelDOC 使用 AGPL-3.0，PyMuPDF/MuPDF 也涉及 AGPL。适配层、缓存位置修改、上游地址及许可证位置见 [修改与授权说明](../scripts/babeldoc/NOTICE.md)。准备脚本保留上游 Python 源码、许可证和 NeoRead 适配源码。正式分发前需确认整体分发方式与对应源码提供方式符合相关许可证；本次没有制作公开发行包。
